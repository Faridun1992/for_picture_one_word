# Changelog

Важные изменения проекта по датам.

- Завершена TASK-040: закрыт доступ к AdminLTE dashboard для пользователей без роли (разрешены Admin/Super Admin), отключена публичная регистрация, сидер ролей стал повторяемым, а демо-пользователи создаются только в local/testing. Удалена нерабочая связь `User::role()` на отсутствующую модель `ModelHasRole`; API.md теперь отличает текущий dashboard от запланированных CRUD маршрутов.

- Завершена TASK-042: добавлена загрузка четырёх JPEG/PNG/WebP файлов на приватный local Storage, проверка типа/расширения/лимита 5 MiB/разрешения 320–4096/decode и запись метаданных. При замене старые файлы удаляются после commit, при ошибке новые очищаются; схема БД уже подходила. Тесты прошли: 7 image-upload tests (48 assertions), весь MySQL suite — 116 tests (646 assertions).
- Завершена TASK-043: добавлена очередь `images` на Horizon для создания thumbnail/display вариантов при сохранении оригиналов; API использует display variant с fallback на original. Локальный supervisor настроен на пользователя `PROJECT_USER`, образ дополнен PHP `intl`. Вся тестовая suite прошла: 120 tests (669 assertions), Pint и `git diff --check` прошли.
- Завершена TASK-044: добавлены серверная проверка полноты перед публикацией и архивирование без удаления прогресса/изображений/переводов. Изменения статуса и конкурентные изменения редактора сериализуются блокировкой строки уровня. Тесты прошли: 6 новых tests (42 assertions), полный MySQL suite — 126 tests (711 assertions).

Тесты reorder/catalog/publish прошли: 16 tests (97 assertions); полный suite — 129 tests (730 assertions).
- Завершена TASK-046: добавлен защищённый AdminLTE экран статистики по уровням с агрегатами начал, завершений, ответов и подсказок, без персональных данных игроков и изменений схемы. Полный MySQL suite прошёл: 131 tests (737 assertions); Pint и `git diff --check` прошли. Phase 4 завершена.

- Завершена TASK-034: `GET /api/v1/progress`, `GET /api/v1/me` и `PATCH /api/v1/me/settings` работают для текущего Player. Прогресс изолирован, cursor paginated; профиль возвращает серверный баланс/current level, настройки валидируются и сохраняются. Настройки по умолчанию: sound/haptics on, theme system. Feature-тесты прогресса/настроек прошли.
- TASK-030 проверена и дополнена: Sanctum bearer authentication восстанавливает именно `Player`, защищённые игровые маршруты отвергают токен `User`, а guest с `user_id = NULL` продолжает работать. Тесты подтвердили выдачу токена для `Player`, тип `auth()->user()`, 401 без токена, устойчивость данных прогресса/кошелька/ledger при связывании того же Player с User и защиту от подмены `player_id`. Проверка выявила и устранила дефект `GET /me`: контроллер внедрял пустую модель вместо аутентифицированного Player.
- Завершена TASK-027: создано хранилище idempotency-результатов с уникальностью `(player_id, key)`, canonical request hash и timestamp финального статуса. Операция и ответ фиксируются одной транзакцией; повторы возвращают сохранённый статус/тело, другой запрос получает 409. Ежедневная очистка удаляет только завершённые записи старше 30 дней от `completed_at`; in-progress записи TTL не затрагивает. Тесты replay, mismatch, rollback и границы срока хранения прошли.
- Завершена TASK-035: игровые API используют `auth:sanctum` + `player` и named rate limiter (120/min на Player, 600/min на IP); guest creation остаётся 10/min на IP. Проверены границы авторизации, Form Request validation и отдельный лимит каждого Player.
- Утверждена начальная экономика MVP: единственная валюта Coins, стартовые +300, rewards за ответ/уровень/milestones/daily/streak/rewarded ad, цены трёх подсказок и ограничения rewarded/interstitial ads; все суммы расположены в серверной конфигурации.
- Завершены TASK-032/033/036: попытки считают правильность на сервере; первое решение начисляет +10 за ответ и +50 за завершение, milestones выдаются один раз; гостевой Player получает +300 через ledger; три подсказки стоят 30/40/100 Coins, неверные плитки выбираются сервером. Wallet/progress/idempotency result фиксируются транзакционно, запросы одного Player сериализуются row lock. Целевые SQLite feature tests прошли (57 tests, 348 assertions); полный PHPUnit suite внутри Docker/MySQL прошёл (98 tests, 572 assertions). MySQL одновременные запросы отдельно не запускались; игровые операции используют row lock строки Player и кошелька.
- Игровые миграции применены к локальной MySQL-БД `laravel`; `migrate:status` подтверждает, что все миграции имеют статус `Ran`.
