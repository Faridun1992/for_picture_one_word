# Техническое задание: «4 картинки 1 слово»

Статус: требования уточняются по мере разработки; фактическая реализация отслеживается в `TASKS.md` и `CHANGELOG.md`.

## Цель и границы

Создать игру для Android и iOS, где игрок связывает четыре изображения с одним словом, выбирает буквы и получает серверно подтверждённый прогресс. Первая версия должна быть понятна одному разработчику, использовать существующие знания HTML/CSS/JavaScript/PHP и допускать развитие без микросервисов.

## Игровой цикл

1. Игрок выбирает «Играть» или продолжает последний доступный уровень.
2. Клиент загружает активный уровень на выбранном языке: четыре изображения, категорию, сложность, длину ответа и перемешанный набор букв.
3. Игрок нажимает буквы. Каждая плитка выбирается только один раз; нажатие на заполненную ячейку или кнопку удаления снимает соответствующую букву. Свободные плитки можно выбрать повторно.
4. При заполнении всех ячеек клиент отправляет собранную строку. Сервер нормализует её с учётом Unicode и языка и сравнивает с серверным ответом.
5. При правильном ответе сервер один раз фиксирует прохождение и награду. Клиент показывает результат и открывает следующий уровень. При неверном ответе сервер не завершает загадку и не меняет валюту; счётчик попыток может увеличиться.

Подсказки MVP: открыть ещё не открытую правильную букву, удалить серверно выбранные неправильные плитки, показать правильный ответ. Подсказка открытия буквы стоит 60 Coins и открывает ровно одну ещё не открытую позицию; сервер выбирает первую закрытую позицию слева направо. Остальные цены и число удаляемых плиток задаются серверной конфигурацией. Списание и состояние подсказки фиксируются одной транзакцией в append-only журнале валюты; повтор запроса с тем же `Idempotency-Key` не списывает Coins второй раз.

Экономика MVP использует только Coins. Новый Player получает один раз +300 Coins. За правильный ответ выдаётся +10 Coins, за завершение загадки дополнительно +50 Coins; milestones за 50/100/500/1000 решённых загадок дают одноразово +150/+300/+300/+500 Coins. Подсказки стоят: `reveal_letter` — 60, `remove_wrong_letters` — 40, `reveal_answer` — 100 Coins. Daily Challenge даёт +100 Coins за первое успешное прохождение конкретной задачи; пропуск не наказывается. Серия из 5/10 правильных ответов даёт +20/+50 Coins. Rewarded Ad даёт +50 Coins после серверной проверки SDK и ограничен 5 наградами в сутки на Player. Денежные значения принадлежат серверной конфигурации; клиент отправляет только намерение выполнить действие.

## Игровой экран и визуальное направление

- Приложенные скриншоты задают композицию и настроение, но не являются макетом для копирования: интерфейс должен выглядеть аккуратно, современно и как мобильная игра, с собственной согласованной палитрой и иконками.
- Игровой экран включает верхнюю панель уровня/прогресса и баланса, сетку 2×2 из четырёх изображений, ячейки ответа, буквенные плитки и доступную кнопку подсказки.
- На типовом портретном экране плитки располагаются в два ряда по шесть; на других размерах сетка адаптируется, но набор всегда содержит ровно 12 отдельных плиток и ни одна не обрезается.
- Набор включает все графемы правильного ответа с нужной кратностью и дополнительные отвлекающие плитки, заданные администратором, до общего количества 12; порядок перемешивается на выдаче. Для ответа из 12 графем дополнительные плитки не добавляются.
- Длина каждого локализованного ответа ограничена 12 Unicode grapheme clusters. Админка проверяет ограничение при сохранении перевода и публикации.
- Справа от плиток отображается кнопка `A` с ценой 60 Coins. После успешного серверного запроса открывается одна первая слева ещё не открытая буква; баланс и ответ меняются только по подтверждённому API результату. При нехватке монет игровое состояние остаётся прежним.
- Главный экран следует той же визуальной системе: заметное действие «Играть/Продолжить», баланс и профиль, второстепенные разделы в понятной навигации. Если есть незавершённый уровень, главный экран показывает карточку именно этого уровня (номер/прогресс и доступные изображения) и действие «Продолжить»; не подменяет его следующим уровнем. Если незавершённого уровня нет, показывает следующий доступный уровень и действие «Играть».

Порядок восстановления уровня определяется серверным `current_level_id`: в первую очередь возвращается доступная незавершённая загадка; клиентский черновик выбранных букв/открытых подсказок восстанавливается только для того же Player, языка и `content_version`. Если сервер не сообщает незавершённый уровень, приложение начинает следующий доступный. UI не должен считать локальный черновик завершённым прогрессом.

## Локализация и Unicode

- Языковые теги API: `ru`, `tj`, `en`; таблица переводов допускает новые BCP 47 коды без изменения схемы.
- `tj` означает таджикский язык. Для отображения используются Unicode строки UTF-8 и шрифт с покрытием таджикской кириллицы (включая `Ғ ғ`, `Ӣ ӣ`, `Қ қ`, `Ӯ ӯ`, `Ҳ ҳ`, `Ҷ ҷ`).
- Ответ хранится как отображаемая строка и как нормализованная форма. Сравнение использует Unicode NFC, полное Unicode case folding и повторную NFC нормализацию. Сейчас обрезаются пробелы по краям, внутренние пробелы/дефисы сохраняются. Нельзя подменять похожие кириллические символы латинскими или сводить специфические буквы к русским.
- Буквенные плитки — массив строк-графем, а не байты или предположительные однобайтовые символы. Клиент использует сегментацию графем (например, `Intl.Segmenter` с fallback), сервер — `intl`/`mbstring`; правила покрываются тестами для `ru`, `tj`, `en`.
- Сортировка переводов не нужна для игрового цикла. Если появится сортировка, применяется локаль, а не сравнение байтов.

### Полная локализация мобильного приложения

- Поддерживаемые языки мобильного UI: русский (`ru`), таджикский (`tj`) и английский (`en`). При выборе `ru` весь видимый интерфейс отображается на русском; при выборе `tj` — на таджикском. Язык применяется сразу ко всем экранам и сохраняется в настройках Player.
- Локализуются все строки приложения, а не только заголовки: кнопки, навигация, подписи и подсказки, игровые состояния, ошибки API/сети, загрузка, пустые состояния, подтверждения, диалоги, accessibility labels и системные сообщения, формируемые самим UI.
- Каждая новая мобильная страница, функция или раздел добавляется сразу со строками на всех поддерживаемых языках. Нельзя считать задачу завершённой или выпускать новый UI с отсутствующими переводами.
- Строки интерфейса находятся в централизованных locale-файлах/каталогах, а не вшиваются непосредственно в компоненты. Для динамических значений используются параметризованные шаблоны; числа, даты, множественные формы и валютные отображения форматируются с учётом выбранной locale.
- Запрещён незаметный fallback на русский при выбранном таджикском (или наоборот). Недостающий ключ выявляется автоматической проверкой/тестом переводов до релиза; в development он должен быть явно заметен. Динамические названия категорий и содержимое уровня запрашиваются на выбранной locale из API; перевод другого языка не подставляется без явного продуктового правила.
- При смене языка клиент синхронизирует locale через `PATCH /api/v1/me/settings`, обновляет все UI-строки и запрашивает локализованные каталог/уровень. Черновик ответа восстанавливается только при совпадении Player, `level_id`, locale и `content_version`.

## MVP

- Гостевой профиль, язык, настройки звука/вибрации.
- Главный экран: продолжить игру, ежедневная задача при наличии, категории и настройки.
- Главный экран восстанавливает последний незавершённый уровень (`current_level_id`); локальный черновик букв восстанавливается из кэша для того же игрока, языка и версии контента.
- Игровой экран, обычные уровни, три серверные подсказки, Coins и переход дальше.
- Laravel JSON API, MySQL, Redis для очередей/кэша при наличии реальной нагрузки, файловое хранилище Laravel Storage.
- Web-admin для управления уровнями, переводами и четырьмя изображениями; публикация только после проверки полноты.
- Доступ к AdminLTE и административным операциям предоставляется только назначенным web-ролям; обычная публичная регистрация пользователей отключена.
- Редактор может сохранять незавершённый черновик; перевод содержит отображаемый ответ и набор буквенных плиток. Публикация, проверка полноты и изображения выполняются отдельными действиями после полной валидации.
- Кэш ближайших загруженных уровней и локальный незавершённый ввод. Офлайн прохождение не засчитывается до проверки сервером.
- Базовые события аналитики через внутренний интерфейс-адаптер и журнал прохождений; без привязки к поставщику аналитики.

Не входят в базовый игровой цикл MVP: рейтинги, социальные функции, магазин, реальные платежи и полная офлайн-игра. Rewarded/interstitial ads, streak и daily challenge имеют отдельные задачи; их утверждённые правила экономики приведены выше. Таблицы под будущие функции не добавляются заранее без обоснованной задачи.

## Функциональные требования

- Уровень имеет постоянный ID и одну сущность задачи; ответы, плитки и тексты локализуются отдельными строками перевода.
- Уровень публикуется только если задана категория, сложность, ровно четыре валидных изображения и перевод ответа/плиток на все обязательные языки MVP; каждый ответ содержит от 1 до 12 графем, а каждый набор выбора — ровно 12 плиток.
- Администратор может создавать, редактировать, архивировать, сортировать и включать/выключать уровни; удаление опубликованного уровня по умолчанию — архивирование, чтобы не разрушать историю игроков.
- Публикация проверяет категорию, все обязательные локали, покрытие буквенного набора правильным ответом и доступность четырёх исходных изображений; архивирование не удаляет уровень, изображения или прогресс игроков.
- Администратор видит агрегированную статистику начала и завершения уровней, числа ответов и подсказок без идентификаторов игроков.
- API не принимает от клиента значение баланса, награды, правильность ответа, номер следующего уровня или статус прохождения.
- Прогресс хранится на сервере. На устройстве хранится кэш контента и незавершённая сессия; очередь синхронизации ограничена безопасными операциями, а не свободной записью прогресса.
- Повторный запрос с тем же ключом идемпотентности возвращает прежний результат. Повторное прохождение не начисляет награду повторно.

## Нефункциональные требования

- Android и iOS; адаптивная сетка для малых и больших экранов, safe areas, крупные touch targets, VoiceOver/TalkBack метки, reduced motion, состояния загрузки/ошибки/пустого списка.
- Поддержка светлой и тёмной темы, вибрации и звука с настройками пользователя.
- Изображения не хранятся в БД: приватный локальный диск при разработке, Laravel Storage для смены на S3-compatible storage/CDN. Очередь создаёт thumbnail до 320×320 и display до 1280×1280, сохраняет исходный формат и оставляет оригинал источником/fallback.
- Для API — TLS, валидация, авторизация, ограничение частоты, журналирование критичных операций и минимизация персональных данных.
- Web-admin принимает набор из четырёх JPEG/PNG/WebP изображений до 5 MiB каждое и размером 320–4096 px по каждой стороне. Файлы лежат в приватном Laravel Storage, клиент не выбирает disk/path/position вне допустимого набора.
- Наблюдаемость: ошибки API, неуспешные синхронизации, использование подсказок и воронка уровней; аналитические события не содержат лишних персональных данных.

## Критерии приёмки MVP

- Новый гость получает отдельный `Player` без создания web-учётной записи `User` и может играть на каждом из трёх языков.
- Unicode ответы, в том числе таджикские буквы, отображаются, выбираются и сравниваются без потери символов.
- Неверный ответ увеличивает только счётчик попыток, не завершает загадку и не меняет баланс; повторная отправка успешного ответа не дублирует награду.
- Покупка подсказки атомарно списывает монеты один раз; при недостатке средств состояние не меняется.
- Прерванный уровень восстанавливает выбранные плитки локально; после потери сети пользователь видит понятное состояние и может повторить безопасный запрос.
- Администратор не может опубликовать уровень с отсутствующим переводом или отличным от четырёх числом изображений.
- Авторизованный запрос не получает чужой прогресс; неподтверждённые данные клиента не меняют экономику.

## Допущения и вопросы для решений

- Для MVP выбрана отдельная сущность `Player`: гость получает Sanctum bearer token без фиктивных email/password. `User` остаётся web/registered account; nullable `players.user_id` позволяет позже привязать существующий игровой профиль без смены `player.id` и потери прогресса. Device ID не является единственной идентичностью.
- Для начала достаточно одного основного ответа на каждом языке; список допустимых альтернатив можно добавить по фактическим данным редакции.
- Правила начальной экономики MVP утверждены в TASK-032/033; суммы настраиваются в `config/game.php`.
- Текущий репозиторий содержит Laravel 13/PHP 8.5.11 и инфраструктурные зависимости. Composer поддерживает `^8.5`; Docker runtime local/stage/prod, Supervisor и CI закреплены на 8.5.11.
- Аудит показал, что текущая `users` миграция требует email и пароль, а `User` содержит дополнительные атрибуты, отсутствующие в фактической таблице. Принятое решение: не менять обязательные поля `users`, а хранить игровой профиль отдельно в `players`; устранение устаревших `User` fillable полей требует отдельного аудита.
- Работающая MySQL подтвердила 9 колонок `users` и успешное применение четырёх существующих миграций. PHP runtime включает `intl`, а Composer требует это расширение для поддержки Unicode NFC.
- Базовая инфраструктура мобильного клиента, Sanctum и Player API реализована. TASK-050 добавляет мобильное создание гостевой сессии, восстановление профиля через `/api/v1/me`, завершение сессии и защищённое хранение bearer token на Android/iOS. TASK-057/058 добавляют локальный IndexedDB кэш игрового контента и черновика ответа, а также безопасное восстановление незавершённых операций по исходному `Idempotency-Key`; сборки и игровые циклы на устройствах проверяются в TASK-059.
