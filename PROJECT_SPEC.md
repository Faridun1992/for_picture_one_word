# Техническое задание: «4 картинки 1 слово»

Статус: проектирование, 27.09.2026. Этот документ описывает целевую игру; существующий Laravel-код пока не является её реализацией.

## Цель и границы

Создать игру для Android и iOS, где игрок связывает четыре изображения с одним словом, выбирает буквы и получает серверно подтверждённый прогресс. Первая версия должна быть понятна одному разработчику, использовать существующие знания HTML/CSS/JavaScript/PHP и допускать развитие без микросервисов.

## Игровой цикл

1. Игрок выбирает «Играть» или продолжает последний доступный уровень.
2. Клиент загружает активный уровень на выбранном языке: четыре изображения, категорию, сложность, длину ответа и перемешанный набор букв.
3. Игрок нажимает буквы. Каждая плитка выбирается только один раз; нажатие на заполненную ячейку или кнопку удаления снимает соответствующую букву. Свободные плитки можно выбрать повторно.
4. При заполнении всех ячеек клиент отправляет собранную строку. Сервер нормализует её с учётом Unicode и языка и сравнивает с серверным ответом.
5. При правильном ответе сервер один раз фиксирует прохождение и награду. Клиент показывает результат и открывает следующий уровень. При неверном ответе сервер не завершает загадку и не меняет валюту; счётчик попыток может увеличиться.

Подсказки MVP: открыть ещё не открытую правильную букву, удалить серверно выбранные неправильные плитки, показать правильный ответ. Цены и число удаляемых плиток задаются серверной конфигурацией. Состояние подсказки, списание и возможная награда за завершение выполняются в одной транзакции и отражаются в append-only журнале валюты. Повторное прохождение не выдаёт повторную награду.

Экономика MVP использует только Coins. Новый Player получает один раз +300 Coins. За правильный ответ выдаётся +10 Coins, за завершение загадки дополнительно +50 Coins; milestones за 50/100/500/1000 решённых загадок дают одноразово +150/+300/+300/+500 Coins. Подсказки стоят: `reveal_letter` — 30, `remove_wrong_letters` — 40, `reveal_answer` — 100 Coins. Daily Challenge даёт +100 Coins за первое успешное прохождение конкретной задачи; пропуск не наказывается. Серия из 5/10 правильных ответов даёт +20/+50 Coins. Rewarded Ad даёт +50 Coins после серверной проверки SDK и ограничен 5 наградами в сутки на Player. Денежные значения принадлежат серверной конфигурации; клиент отправляет только намерение выполнить действие.

## Локализация и Unicode

- Языковые теги API: `ru`, `tj`, `en`; таблица переводов допускает новые BCP 47 коды без изменения схемы.
- `tj` означает таджикский язык. Для отображения используются Unicode строки UTF-8 и шрифт с покрытием таджикской кириллицы (включая `Ғ ғ`, `Ӣ ӣ`, `Қ қ`, `Ӯ ӯ`, `Ҳ ҳ`, `Ҷ ҷ`).
- Ответ хранится как отображаемая строка и как нормализованная форма. Сравнение использует Unicode NFC, полное Unicode case folding и повторную NFC нормализацию. Сейчас обрезаются пробелы по краям, внутренние пробелы/дефисы сохраняются. Нельзя подменять похожие кириллические символы латинскими или сводить специфические буквы к русским.
- Буквенные плитки — массив строк-графем, а не байты или предположительные однобайтовые символы. Клиент использует сегментацию графем (например, `Intl.Segmenter` с fallback), сервер — `intl`/`mbstring`; правила покрываются тестами для `ru`, `tj`, `en`.
- Сортировка переводов не нужна для игрового цикла. Если появится сортировка, применяется локаль, а не сравнение байтов.

## MVP

- Гостевой профиль, язык, настройки звука/вибрации.
- Главный экран: продолжить игру, ежедневная задача при наличии, категории и настройки.
- Игровой экран, обычные уровни, три серверные подсказки, Coins и переход дальше.
- Laravel JSON API, MySQL, Redis для очередей/кэша при наличии реальной нагрузки, файловое хранилище Laravel Storage.
- Web-admin для управления уровнями, переводами и четырьмя изображениями; публикация только после проверки полноты.
- Кэш ближайших загруженных уровней и локальный незавершённый ввод. Офлайн прохождение не засчитывается до проверки сервером.
- Базовые события аналитики через внутренний интерфейс-адаптер и журнал прохождений; без привязки к поставщику аналитики.

Не входят в базовый игровой цикл MVP: рейтинги, социальные функции, магазин, реальные платежи и полная офлайн-игра. Rewarded/interstitial ads, streak и daily challenge имеют отдельные задачи; их утверждённые правила экономики приведены выше. Таблицы под будущие функции не добавляются заранее без обоснованной задачи.

## Функциональные требования

- Уровень имеет постоянный ID и одну сущность задачи; ответы, плитки и тексты локализуются отдельными строками перевода.
- Уровень публикуется только если задана категория, сложность, ровно четыре валидных изображения и перевод ответа/плиток на все обязательные языки MVP.
- Администратор может создавать, редактировать, архивировать, сортировать и включать/выключать уровни; удаление опубликованного уровня по умолчанию — архивирование, чтобы не разрушать историю игроков.
- API не принимает от клиента значение баланса, награды, правильность ответа, номер следующего уровня или статус прохождения.
- Прогресс хранится на сервере. На устройстве хранится кэш контента и незавершённая сессия; очередь синхронизации ограничена безопасными операциями, а не свободной записью прогресса.
- Повторный запрос с тем же ключом идемпотентности возвращает прежний результат. Повторное прохождение не начисляет награду повторно.

## Нефункциональные требования

- Android и iOS; адаптивная сетка для малых и больших экранов, safe areas, крупные touch targets, VoiceOver/TalkBack метки, reduced motion, состояния загрузки/ошибки/пустого списка.
- Поддержка светлой и тёмной темы, вибрации и звука с настройками пользователя.
- Изображения не хранятся в БД: локальный диск при разработке, абстракция Laravel Storage для смены на S3-compatible storage/CDN. Создание оптимизированных размеров в очереди; оригинал остаётся источником. WebP/AVIF выбираются после проверки поддержки платформ и стоимости декодирования.
- Для API — TLS, валидация, авторизация, ограничение частоты, журналирование критичных операций и минимизация персональных данных.
- Наблюдаемость: ошибки API, неуспешные синхронизации, использование подсказок и воронка уровней; аналитические события не содержат лишних персональных данных.

## Критерии приёмки MVP

- Новый гость получает отдельный `Player` без создания web-учётной записи `User` и может играть на каждом из трёх языков.
- Unicode ответы, в том числе таджикские буквы, отображаются, выбираются и сравниваются без потери символов.
- Неверный ответ увеличивает только счётчик попыток, не завершает загадку и не меняет баланс; повторная отправка успешного ответа не дублирует награду.
- Покупка подсказки атомарно списывает монеты один раз; при недостатке средств состояние не меняется.
- Прерванный уровень восстанавливает выбранные плитки локально; после потери сети пользователь видит понятное состояние и может повторить безопасный запрос.
- Администратор не может опубликовать уровень с отсутствующим переводом или отличным от четырёх числом изображений.
- Авторизованный запрос не получает чужой прогресс; неподтверждённые данные клиента не меняют экономику.

## Допущения и вопросы для решений

- Для MVP выбрана отдельная сущность `Player`: гость получает Sanctum bearer token без фиктивных email/password. `User` остаётся web/registered account; nullable `players.user_id` позволяет позже привязать существующий игровой профиль без смены `player.id` и потери прогресса. Device ID не является единственной идентичностью.
- Для начала достаточно одного основного ответа на каждом языке; список допустимых альтернатив можно добавить по фактическим данным редакции.
- Правила начальной экономики MVP утверждены в TASK-032/033; суммы настраиваются в `config/game.php`.
- Текущий репозиторий уже содержит Laravel 13/PHP 8.4 и инфраструктурные зависимости, но его пригодность как игрового backend и состояние миграций требуют аудита перед реализацией.
- Аудит показал, что текущая `users` миграция требует email и пароль, а `User` содержит дополнительные атрибуты, отсутствующие в фактической таблице. Принятое решение: не менять обязательные поля `users`, а хранить игровой профиль отдельно в `players`; устранение устаревших `User` fillable полей требует отдельного аудита.
- Работающая MySQL подтвердила 9 колонок `users` и успешное применение четырёх существующих миграций. PHP 8.4 контейнер теперь включает `intl`, а Composer требует это расширение для поддержки Unicode NFC.
- Базовая инфраструктура мобильного клиента и Sanctum установлена; добавлен API health endpoint `/api/v1/health`. Player-модель, гостевая выдача токена и игровые endpoints ещё не реализованы; продолжение — TASK-020.
